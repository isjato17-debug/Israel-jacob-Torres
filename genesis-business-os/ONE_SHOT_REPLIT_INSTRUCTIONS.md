# GENESIS BUSINESS OS — ONE-SHOT REPLIT MASTER

## Product authority
Brand: GENESIS BUSINESS OS
Promise: Start With What You Have. Build Toward What You Want.
Consumer rule: Power underneath. Simplicity on top.

## Consumer navigation
Home | My Business | Do It | Community | Ask Genesis

## Core journey
Welcome -> Founder Reality -> Choose Path -> Destination -> Route Portfolio -> Next Turn -> Do It With Genesis -> Proof Checkpoint -> Track Real Results -> Dependency Reroute -> Next Turn -> Destination -> Set Next Goal.

## Do not redesign the product into an engineering dashboard
Ordinary users should not need to understand Business Genome, Digital Twin, Filing Graph, Decision Ledger, agent orchestration, evidence ledger, or authorization architecture. Surface these only as plain-language outcomes or advanced details.

## Merge requirements
1. Treat `backend/` as the primary app backend and preserve its security controls.
2. Treat `frontend/index.html` and `docs/GENESIS_FULL_JOURNEY_VISUAL.png` as consumer UX references. Bring the backend-served static UI into alignment with them.
3. Integrate `backend/app/route_engine.py` as the route/reroute mechanism.
4. Integrate `execution_layer/app/` into the backend service layer. Do not create a second standalone server for it.
5. Preserve Community endpoints and privacy-by-default behavior.
6. Every actionable CTA must be typed EXECUTE, PREPARE, or GUIDE.
7. Never claim an external action succeeded without provider evidence/receipt.
8. Tier-3 external communication/spend/configuration requires explicit user approval. Tier-4 autonomous execution remains disabled.
9. A Proof Checkpoint advances only from verified evidence, not a checkbox.
10. Material changes update only dependent assumptions, requirements, financial projections, tasks and route steps.

## Live provider rule
Provider-dependent features must remain visibly `Not connected` / `Prepared` / `Guided` until a real approved provider, account, API permission, webhook and production credential exist. Never add fake success responses.

## Production data/security
Use production PostgreSQL. Fail closed if production secrets/config are missing. Enforce tenant/resource authorization server-side, secure revocable sessions, CSRF, secure cookies, rate limits, trusted hosts/origins, safe uploads, SSRF defenses, scoped tool capabilities, audit records, and no secrets/auth tokens in browser storage.

## Replit start
The root `.replit` runs the FastAPI backend on port 3000. Static consumer UI should be served by the backend.

## Acceptance target
A new user can: create a profile -> enter actual resources -> set destination -> receive candidate route -> see one next turn -> prepare/guide/execute a supported action -> provide/receive evidence -> pass/fail proof checkpoint -> record actual result -> reroute -> participate in Community without exposing private business state -> ask Genesis questions throughout.
